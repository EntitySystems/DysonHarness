# Meta Agent mode

Never-blocking orchestrator plus isolated implementer. Page-launched; not in the composer mode picker. Storage: [plans.md](../storage/plans.md). UI: [UI README](../ui/README.md)#meta-agent-page. The shared compaction path is in [README.md](README.md)#context-compaction; the Meta Agent specifics (180K pin, reasoning always preserved) are under [Context](#context-180k-cap-compaction-reasoning) below. This page is the toolset, plan tools, and the child-report loop.

## Modes

`DysonAgentModes.MetaAgent` (`"Meta Agent"`) and `MetaAgentDrone` (`"Meta Agent Drone"`) are in `BuiltIns`. Neither is in `ComposerSelectable`. The page-launched root is not in the work-session list and is not user-deletable (`Meta Agent sessions cannot be deleted.`). `DeleteMetaAgent` still deletes terminal drones. Directives: `DysonAgentSystemPrompts.MetaAgentDirective` / `MetaAgentDroneDirective`. Child first turns prepend `SubagentReportRequiredMandate`; Meta Agent Drone also gets `MetaAgentDroneFirstTurnMandate`. Default provider: `DysonAgentSessionConfig.MetaAgentDroneDefaultProvider` (same omit-slug cascade as Drone). Settable at Settings → Agent behavior via `meta_agent_drone_model_slug_id` (effort: `meta_agent_drone_reasoning_effort`); empty inherits the parent chat model, and an explicit spawn `modelSlug` still wins.

`ValidateSubagentSpawn` (`DysonMetaAgentSpawnGateTests`):

- Meta Agent → Meta Agent Drone, Explore, Bug Review, or Security Review. Meta Agent itself cannot be a child (`"Meta Agent cannot be used as a subagent mode (page-launched only)."`).
- Meta Agent Drone → Explore, classic Drone, Bug Review, or Security Review. Nested Meta Agent Drone is rejected (`"No multi-layer Meta Agent Drones; spawn a Drone or Explore."`).
- Classic Drone is still Explore only (`"Drone may only spawn Explore subagents."`). Explore still cannot spawn, including these reviews (`"Explore cannot spawn subagents."`).
- Anyone else spawning Meta Agent Drone is rejected (`"Meta Agent Drone may only be spawned by a Meta Agent session."`).

## Toolset (allowlist strip)

`DysonSessionToolsetBuilder.ApplyModeCatalog` runs **after** default catalog, inter-agent depth, completion omit, plugin/custom merge, and the mode denylist. Meta Agent is an allowlist, not a denylist: everything not in `DysonMetaAgentTools.AllowedToolNames` is removed except `CreateBrowserTools` names already on the pipeline, shared schemas (todos, `GetOpenRulesConfig`, `LoadSkill`) are restored from a no-browser `CreateDefault`, then meta-only tools are added. Browser tools are not copied back, so a denylist removal and a null `BrowserControl` both stay absent. `OmitRootTaskCompletionTools` also runs — a meta session never completes.

Enforced list: `DysonMetaAgentTools.ExcludedToolNames`, asserted by `DysonMetaAgentNoFileAccessTests` (catalog contains none of those names, does contain `LoadSkill` + `GetOpenRulesConfig`, and no plan-tool schema accepts a `path` argument). `DysonMetaAgentToolsetTests` asserts the live catalog **is exactly** `AllowedToolNames` when `BrowserControl` is null and `Config.Voice` is null, and that a non-null control (including `DysonNullBrowserControl`) keeps every `CreateBrowserTools` name while file and shell tools stay absent. `SpeakToUser` is not in `AllowedToolNames` and is not on the Meta catalog. While `Config.Voice` is non-null the root Meta Agent catalog adds `MessageVoiceModeSidecar` instead. Voice off removes it. Meta Agent Drone never gets either tool.

### Scratch notes

Root Meta Agent only (`ListNotes`, `CanCreateNote`, `CreateNote`, `UpdateNote`, `DeleteNote`). Not on the drone, Work, Explore, or Plan catalogs. Files are `.dyson/scratch/*.md` on the session work root, already gitignored by `**/.dyson/`. `DysonScratchNotes.CheckWriteAsync` is the one scan for the roster and the budget: 20 notes, 1000 tokens each (`DysonTiktokenTokenCounter`), 20000 total. `ListNotes` returns `{name, tokens}` sorted by name and nothing else. There is no `ReadNote`, and note text is not copied into the system prompt. `CanCreateNote` returns `allowed`, `reason`, `noteCount`, `totalTokens`, `noteTokens`, and the three caps — no names and no bodies. Create and update call that check; they do not remember that `CanCreateNote` ran. Delete has no cap. The directive still opens with "You cannot touch the filesystem" and does not name this directory.

### Scratch files

Database-backed markdown documents in `meta_scratch_files`, not the file-based scratch notes above. Root Meta Agent and Meta Agent Drone both get `CreateMetaScratchFile`, `ReadMetaScratchFile`, `EditMetaScratchFile`, and `DeleteMetaScratchFile` (`DysonMetaAgentTools.CreateScratchTools()`, yielded from `ApplyAllowlist` and `ApplyDroneAllowlist`). Work, Explore, Plan, and the classic Drone do not, and the tools are not on the default catalog. The executor also gates each call with `IsMetaAgentOrDrone()`.

There is no list tool. `ReadMetaScratchFile` without `id` returns the Scratch-tab order as `[{id, title, chars, sortIndex, updatedUtc}]` (no bodies). With `id` it returns the title and full markdown (no 64KiB clip). Each file holds at most 131,072 characters (`IDysonMetaScratchFileRepository.MaxContentChars`); create and edit reject a larger body and save nothing. `DeleteMetaScratchFile` is a hard delete (no archive, no undo) and requires a `reason`, which is logged. `EditMetaScratchFile` uses `DysonTextEditApplier.TryApplyEdits` (all-or-nothing), the same shape as `EditMetaPlan` with `planId` renamed to `id`.

The repository is `DysonAgentSessionConfig.MetaScratchFiles` (children share the config). Null returns `Scratch files are not available in this session (no database).` After a successful create, edit, or delete the executor publishes `DysonMetaScratchFilesChangedEvent` (`WorkDirectoryId`, `ScratchFileId`, no body) on `DysonBusScopes.WorkDirectory`. `MetaScratchList` subscribes and also publishes after a user move or delete. Link a file from `PostConversationMessage` or `PostUserQuestion` with the built-in action key `open_scratch:{id}` (`DysonBuiltInConversationKind.OpenScratch`; the id rides on `DysonBuiltInConversationIntent.PlanId`). Storage: [scratch.md](../storage/scratch.md).

Structurally absent (not an exhaustive list — see `ExcludedToolNames`): file/shell/search tools except `WriteTempFile` and `ReadTempFile` (generated `.dyson/temp/` leaves only), `WaitForSubagent`, `StartSubagent` and the classic subagent quartet, `AskQuestion` / `PromptUserDialog` (they block; a question the user must decide uses non-blocking `PostUserQuestion` instead), completion tools, `SubmitSubagentReport`, `DropTurnContext` / `RestoreTurnContext`, `StartNewTurn` / `ExpandThoughtProcess`, `GetDateTime`, `RenameSession`, `InitializeOpenRules`, `SubmitPlan` / `EditPlan`.

### `LoadSkill` Literal gate

Root + AutoInclude bodies are already in the system prompt. `LoadSkill` still runs `DysonSkillLoader.ResolveAndLoadAsync`, then **post-filters** `Source == DysonSkillSource.Literal` in Meta Agent mode (`DysonMetaAgentTools.LoadSkillLiteralRejectedMessage`). Named skills, `.dyson/skills`, openrules AgentOptional, included `Resources/Skills`, and plugins pass. A work-relative path such as `docs/ui/README.md` is the hole this closes. Covered by `DysonMetaAgentLoadSkillTests`. Post-filter beats a second resolver so resolution changes cannot drift.

### Meta Agent Drone catalog

`ApplyDroneAllowlist`: Work catalog minus `AskQuestionFromParent` and `PromptUserDialogFromParent` only (`TriggerParentEvent` stays), so `ChangeSubagentAIModel` (the `subagentId` variant) is on the drone catalog, plus `ReadMetaPlan`, `EditMetaPlan`, `SubmitMetaPlan`, `CreateMetaScratchFile`, `ReadMetaScratchFile`, `EditMetaScratchFile`, and `DeleteMetaScratchFile`. `PostUserQuestion` is not on the drone. It also adds `StartAsyncBugReviewAgent` and `StartAsyncSecurityReviewAgent` (not `StartAsyncExploreAgent`, not `StartAsyncMetaAgentDrone`). Those reviews use the same `CreateChildAsync` path as Explore and inherit the drone checkout. The drone waits with the `WaitForSubagent` it already has. `StartSubagent` is still how it spawns Explore and classic Drone. The review tools do not take `useWorktree` or `existingWorktreePath`. Questions and section-boundary status pings go up as `TriggerParentEvent` with kind `message`; the parent answers with `RespondToSubagentEvent` — immediately for a status (and posts it to the user), after the user decides for a question. `SubmitSubagentReport` stays. Covered by `DysonMetaAgentToolsetTests`.

Meta parents (`Meta Agent` and `Meta Agent Drone`) always auto-turn every child event, including `askQuestion` and `promptUserDialog`. The focused card may still open and is not the only delivery. Work, Ask, and Plan stay card-only for valid Ask/Dialog JSON. One re-inject (`DysonSubagentHostLogic.MetaParentEventRetryCap = 1`) then the child gets `Parent did not answer this event.` and the root Meta Agent gets a `DisplayInfo` turn. A root `DisplayInfo` parks the event until the next user message carries that same event in `HiddenInstruction`. Depth greater than 1 `askQuestion` / `promptUserDialog` fails fast (`Use kind message.`); the deadlock guard is unchanged. `BuildSubagentEventContinuationPrompt` carries the reply contract on every delivery (the first auto-turn, the one retry, and the parked `HiddenInstruction`), chosen from the receiving session's mode. The system-prompt parent-event sentences are only a backstop.

A parent-event continuation is kind `ParentEvent` (20): it stays in the session transcript and is not a meta-chat bubble, and a posted message may relay the status or question and must not name the event.

### Dispatch shapes (coordinator vs parallel direct)

Every `useWorktree: true` drone is its own merge into the registered checkout. For a code change the root picks one shape (root prompt section "Code changes: one coordinator, or parallel direct drones"):

- **A. Coordinator (default).** One `useWorktree: true` drone owns the whole change. It runs classic Drone workers with `StartSubagent` inside its own worktree (workers inherit the parent's work directory and worktree columns; they never get their own worktree and never merge), gives each worker its own files, integrates, builds and tests once, commits, and reports once. One merge. `BeginBuildPlan` always dispatches shape A (one coordinator per plan; `DysonMetaBuildBrief` says so). The drone directive's "Coordinating workers" section holds the rules: split first, no file in two slices, one worker at a time builds or tests, workers do not commit, never report while a worker runs or `git status` is dirty.
- **B. Parallel direct.** Several `useWorktree: true` drones, each doing its own slice with no workers, only when the slices share no file, type, project file, or config. The root names each drone's files in its brief and writes why they do not overlap in the dispatch todo.

Guard: `DysonMetaAgentTools.MaxRunningWorktreeDrones = 3`. `CreateMetaAgentDroneChildAsync` (shared by `StartAsyncMetaAgentDrone` and a new `BeginBuildPlan` spawn) takes `DysonAgentSession.WorktreeDroneSpawnGate` (per root session `SemaphoreSlim`, so same-stage calls cannot both pass) when `useWorktree` is true, counts live Meta Agent Drone children with a non-null `WorktreeBranch`, and returns a Result error at the cap (`"{n} useWorktree true drones are already running (#a, #b, #c); the limit is 3. ..."`). Process-local, live drones only: terminal drones (including a `Failed` conflicted drone still holding its worktree), `useWorktree: false` drones, and `existingWorktreePath` resolvers do not count. `BeginBuildPlan` with `agentId` does not spawn and is not capped. Covered by `DysonWorktreeDroneCapTests`.

Workers: `BuildChildFirstPrompt(parentMode, agentMode, ...)` adds `DysonAgentSystemPrompts.MetaAgentDroneWorkerFirstTurnMandate` ("Coordinated worker mandate": edit only the named files, no commit/stash/reset/checkout/merge/rebase, build or test only when allowed) after the Drone mandate when a classic Drone's parent is a Meta Agent Drone. A Drone under Work does not get it.

`StartAsyncMetaAgentDrone` requires boolean `useWorktree` (no default). File-mutating tasks should set it true: own git worktree and branch; a completed report merges under `MergeGates`. Non-coding tasks (ops, testing, CI, pushes, read-and-run) should set it false: parent's checkout, no `dyson/` branch, no merge. Optional `existingWorktreePath` is only valid with false: it rebinds tools to an already-listed checkout, does not call `Ensure`, and leaves worktree columns null so that drone's completed report does not merge. False without the path stays on the registered checkout. True still forks. True plus the path errors before spawn. `BeginBuildPlan` still passes true. Explore never merges. Classic drones inherit the parent drone checkout and do not merge on their own report. A content conflict aborts the registered checkout (usable again), leaves the drone worktree, and the failed `SubagentFailed` report is the resolve note. The parent spawns a resolver with `useWorktree` false and `existingWorktreePath` set to that worktree, does not `StopMetaAgentDrone`, does not pass `discardWorktree`, and does not edit files. The conflicted drone stays `Failed` with its columns until the parent messages it to `SubmitSubagentReport` completed, which retries the same merge. The worktree is removed only when that retry succeeds. `EnsureSessionWorktreeIfNeededAsync` still early-returns when `session.Parent is not null`.

### Stale worktrees

`DysonGitInfo.TryRemoveWorktreeAsync` (used by every merge, remove, discard, and abandon path) no longer depends on git still listing the checkout. If the path is not in `git worktree list`, or `git worktree remove` answers `is not a working tree`, it runs `git worktree prune` and deletes a leftover folder only when git still does not list it, then returns success so the caller clears the session's worktree columns. A merge that already succeeded (`Already up to date`, e.g. the work landed as another commit), `DeleteMetaAgent`, and `StopMetaAgentDrone(discardWorktree)` therefore finish on a stale registration. A folder git still lists is never deleted by hand.

When the remove or folder delete fails because something holds the folder (`Invalid argument`, access denied, in use), the harness kills processes whose executable path (`MainModule`) is under that worktree folder (`DysonGitInfo.IsPathUnder`: full path plus trailing separator, so `…\abc` never matches `…\abcd`; drive roots never match), never the current process and never anything under the registered checkout, then retries three times (250 ms, 500 ms, 1 s). That covers an orphaned `testhost.exe` from the drone's own test run. A process outside the folder is never killed.

## Voice mode

Root Meta Agent only (`Parent` is null and `DysonSessionPolicy.IsMetaAgent`). Not a Meta Agent Drone, and not any other mode. Windows only: `DysonVoiceMode` is scoped under `#if WINDOWS` beside `DysonSpeechTryout`. Off Windows the service is missing and the button title is "Voice mode needs the Windows app."

One voice service per subject, shared by every work directory. `DysonSessionRuntime` (retained per subject by `DysonSessionRuntimeRegistry`) takes `DysonWorkDirectoryFocus` and the optional `DysonVoiceMode` from its retained scope; the Blazor circuit never resolves `DysonVoiceMode` (`VoiceModeButton` reads `DysonUiHost.Voice`). Voice mode is app-wide: it stays on across session, Settings, Home, and work-directory changes, until the user clicks it off or the app exits.

`StopAsync(DysonVoiceStopReason)` stops the loops, the mic, and playback only for `UserOff` (button click-off) and `AppExit` (`DysonSessionRuntime.DisposeAsync`). `PageDispose`, `SessionSwitch`, `WorkDirectorySwitch`, and `Settings` return at once and leave `IsOn` true. A remounted button adopts `IsOn` without calling `StartAsync` again.

Activation sentence. Once `StartAsync` sets `IsOn`, it fires (not awaited) one cached clip from the active TTS voice: "Voice mode activated. Please wait up to five seconds for all systems to initialize." This is not the listen cue, not the accept cue, and not a beep; it plays through `PlayListenCue(clip)` with a non-null clip only. The clip is `{installRoot}/activation-sentence.wav` plus `activation-sentence.txt` (runtime id, resolved voice id, the fixed sentence; `DysonActivationSentence`). A miss, including a changed model or voice, synthesizes once in the background (`SynthesizeAsync`, `voiceId` null; over 15 s of audio is not cached). Any failure is silent and leaves voice mode on. The already-on return does not replay, and a run turned off before the clip is ready does not play it. "Five seconds" is only words: no wait is inserted.

Turning on calls `SetVoiceMode(shared)` on every live root meta session (and on any root meta session loaded or created later while on); turning off clears all of them. `DysonUiHost` owns `MessageReady` / `Failed` for the whole on interval and prompts the same in-memory root meta session the page is showing for `DysonWorkDirectoryFocus.ActiveId` (adopt that instance; do not load another). There is one `InFlightPromptTurn`. No active work directory, or no meta session there, raises `Failed`; the listen loop never creates a session and never prompts a Work session.

Speech is one queue: `Channel<SpokenLine>` (`Text`, `WorkDirectoryId`, `WorkDirectoryName` snapshot), single reader `SpeakLoop`, one playback at a time. The loop plays prepared chunks (`DysonSpeechTryout.PlayPreparedAsync`): synthesis is pumped into a channel so it is not inside the play await. It synthesizes at most the next dequeued line while the current line is playing, and drops that line on barge-in and stop. `PlaybackText` is fixed when that line is dequeued for synthesis: the active work directory is not prefixed; any other line is `Message from workdir {name}: {text}`, where `name` is the live stored name, else the enqueue snapshot (row deleted), else `untitled`. Barge-in cancels the clip in flight and the prefetched line; it does not drain the channel. While `IsCapturing` (wake matched until the `PauseMs` tick), `SpeakLoop` does not start playback. Those lines play in order after that pause.

Owner gate for `ListWorkdirs`, `OpenWorkdirsPanel`, and `SwitchWorkdir` (in `DysonWorkDirectoryFocus`, before any repository call or UI hook): the caller's work directory must equal `ActiveId`, both non-empty. The voice sidecar passes the same gate with its Meta's work-directory id (its own row's `WorkDirectoryId`), so only the on-screen sidecar may use these tools. Otherwise the tool error is exactly `Other work directory owns the application, you can ask the user in voice mode to change directories via MessageVoiceModeSidecar.` (`DysonWorkDirectoryFocus.NotOwnerMessage`) and nothing changes. `ActiveId` is in memory only, written by `Home`, `MetaAgent`, and `SwitchWorkdir`; Settings does not clear it.

Two chimes. Listen cue is the chime (`DysonSpeechTryout.PlayListenCue(null)`, 60 ms, 660 Hz, amplitude 0.04) unless `speech_listen_sentence` is set, in which case the cached clip plays and the chime does not. Once per stored wake-name match, idle or barge-in; not queued, never prefixed, not awaited, never stops or ducks speech (waits for a held play gate, dropped if a new `Speak` takes it first). Accept cue is the chime (`PlayAcceptCue(null)`, 120 ms, 880 Hz, amplitude 0.1) unless `speech_accept_sentence` is set, in which case the cached clip plays and the chime does not. Only when the turn is submitted, and not while speech is already playing.

`DysonAgentSession.SetVoiceMode(DysonVoiceMode?)` sets `Config.Voice`. That flag is not persisted. On a root Meta session, non-null adds `MessageVoiceModeSidecar` (not `SpeakToUser`) and appends `DysonAgentSystemPrompts.MetaAgentVoiceDirective` via `WithVoice(directive, mode, voiceOn)` (`MetaAgentDirective` itself is not edited). Null removes both. The same call is forwarded to the live sidecar. The pipeline is replaced wholesale, so a turn in flight never sees a half-updated catalog; the change applies on the next model request. The button calls `DysonUiHost.SetMetaVoiceModeAsync`, which persists `SystemPromptSnapshot` for each root meta session it changes and calls `EnsureVoiceSidecarAsync` for each live root while voice is on. Only `UserOff` and `AppExit` turn voice off (see above). It does not survive a restart. A sidecar turn already running may finish, but its `SpeakToUser` calls then return that voice mode is off.

### Modes

Three input modes (`DysonVoiceInputMode`). The subject-scoped setting `speech_voice_mode` is `callsign`, `immediate`, or `ptt` (`DysonAppSettingKeys.SpeechVoiceModePushToTalk`); missing, blank, or unknown reads as Callsign. `DysonVoiceMode.Mode` is the in-memory value, loaded by `StartAsync` and by `GetModeAsync`. `SetModeAsync` switches live (even mid-utterance) and persists the key; a persist error leaves the live switch and returns the error. A mode switch does not rebuild the system prompt. Requirements are re-checked whenever voice is on and the mode changes.

- **Callsign Activated** (default). Say one of the eight stored wake names, then talk. A pause posts the message. The pause is `speech_callsign_pause_ms` (default `PauseMs` 3000). `SetPauseAsync` accepts 1000–10000 ms and otherwise returns `"Pause must be between 1 and 10 seconds."` Reads of a missing, blank, non-numeric, or out-of-range value use the default. The composer does not mirror this mode.
- **Immediate.** No callsign. While voice is on, the first decoded word that contains a letter or digit starts an utterance, and `DraftChanged` streams that text (no prefix) into the Meta composer (`VoiceModeButton.OnDraft`). A pause of `speech_immediate_pause_ms` (default `ImmediatePauseMs` 2000, same 1–10 s range) posts it. A wake name said out of habit stays as text. Immediate requires Nemotron (`DysonGgufSpeechModels.NemotronId`); otherwise `Requirements` and `SetModeAsync` return `"Immediate mode needs Nemotron 3.5 live speech-to-text. Pick it in Settings → Voice."` Windowed engines (Phonon, CrispASR, Whisper NPU) are not allowed: a 2 s pause would fire inside a ~2 s window. Wake names are not required for Immediate. `PauseFor` is the cached pause the UI titles use.
- **Push to talk.** Voice mode stays on (TTS, the sidecar's `SpeakToUser`, the picker). The microphone is not opened until Ctrl+M is held (`BeginPushToTalkAsync`); releasing the key (`EndPushToTalkAsync`) cancels only the capture token, the engine flushes its final (Nemotron `FinalizeAndRead`, or one more windowed `TranscribeAsync` of the tail), and the held text is posted at once with no pause wait. `DraftChanged` mirrors the utterance into the composer while held. Works with every STT engine; Nemotron is not required (Phonon drafts update once per ~2 s window). Wake names are not required. PTT ignores the pause (`OnTick` returns null). A hold longer than `MaxHoldMs` (2 min) ends itself. Leaving PTT while held posts what was said; entering PTT mid-capture drops that capture. The mic stays closed during playback unless the key is held, so the key press is the barge-in.

All three modes post `DysonVoiceMessage` (`Text` still starts with `InputPrefix` `"[voice input] "`, plus `Mode`, plus optional `CutOff`) through `MessageReady`. The host does not hand that transcript to the Meta session. `DysonSessionRuntime.RouteVoiceToSidecarAsync` builds the turn with `CreateTurn` on the sidecar and, once the sidecar holds it (injected, interrupted, or queued) and before the drain runs it, posts the prefixed text as a `[voice input]` `DisplayInfo` line on the Meta chat (never in Meta's model context). `DysonVoiceMode.IsVoiceInputDisplay` (a `DisplayInfo` whose text starts with `InputPrefix`) makes `MetaChatItems` render that line as the user's own bubble; the prefix is stored on the turn, so it stays the user after a reload. `ReadMetaAgentLog` skips those lines, so the sidecar does not read the user's words as Meta posts. `CreateTurn` sets `HiddenInstruction` to `DysonAgentSystemPrompts.VoiceSidecarTurnInstruction` for Immediate and Push to talk (first line `[Voice sidecar]`). Callsign turns leave it null, unless the utterance was a barge-in. A barge-in (`CutOff` set, the first 200 characters of the line that was cut) appends `VoiceSidecarCutOffLine`; a Callsign barge-in gets only `VoiceSidecarCallsignCutOffInstruction`. The hidden text is not shown in chat, and summarization drops it. `MetaAgentImmediateVoiceTurnInstruction` is gone. Immediate and PTT never inject a comment into Meta, so every such message is a new turn on the sidecar.

While on, one listen loop reads the growing transcript (`DysonSpeechTryout.RecordAsync`, same mic as Settings). A pure nested `Listener` (time is a `long` millisecond argument) yields three outcomes. `Mode`, the pause, and the post-speech mute are not cleared by `Reset()`.

- **Wake (Callsign).** Exact contiguous token match against one of the eight stored texts in `speech_wake_names`. Tokens are lowercased and reduced to letters and digits. The last match wins. There is no fuzzy match and no hardcoded name; the eight variants are the tolerance for STT spelling. Prompt text starts only at 1.0 s (`PostWakeIgnoreMs`). The same-update tail and any update before that are discarded. The listen cue is not delayed. Switching to Immediate mid-capture keeps the text so far and drops that ignore window.
- **Start (Immediate).** The first letter-or-digit token after the idle mark starts capture, with no ignore window. No listen cue (a cue on every first word would be transcribed). An idle switch ignores chatter heard before it. Push to talk never starts a capture by itself: the mic stays closed until `BeginPushToTalkAsync`.
- **Submit.** More than the mode's pause with no new words, measured from the last counted change (a revised Nemotron partial resets it; in Callsign, updates inside the first second do not). The user message is `InputPrefix` + the rest. The host sends it to the sidecar of the root meta session for the active work directory (`RouteVoiceToSidecarAsync`), never to that Meta session's own turn. Routing is `DysonVoiceRoute` / `RouteFor` via `InterruptsWhenBusy` (Immediate and Push to talk), applied to the sidecar: Callsign injects when the sidecar's turn is in flight, queues when the sidecar is busy or summarizing, and prompts when the sidecar is idle. Immediate and PTT prompt when the sidecar is idle and otherwise interrupt the sidecar (below). An empty rest is dropped and Immediate or PTT raises `DraftChanged("")`. PTT does not wait for the pause: key up takes the held text (`TakeHeld`) and posts at once. Noise only (no letter or digit) and an echo of the last spoken line post nothing.
- **Barge-in.** While TTS is speaking, user speech stops playback at once and those words become the next transcript. A stored wake-name match is still checked first and still plays the listen chime. Any other non-empty partial that is not an echo of the line actually playing (the `PlaybackText` result, workdir prefix included) also barges in when it has one word outside the fillers `um uh hm mm ah oh`, or when non-empty partials have kept arriving for about 300 ms (`SpeechBargeInMs`). That speech barge-in skips the listen chime, keeps the triggering words (Callsign accepts them with no wake name), and sets `CutOff`. In Push to talk the mic is closed during playback unless Ctrl+M is held; key-down still calls `DropPendingSpeech` and plays the 60 ms listen chime (`PlayListenCue(null)`, not a spoken listen sentence). The current clip fades out (`FadeOut`, 150 ms); the in-flight and prefetched synthesis are cancelled, and the model stays loaded. A wake-name barge-in in Callsign still drops the wake word (1.0 s ignore); a speech barge-in does not. In Immediate there is no post-wake ignore window. A PTT hold drops words inside that fade window (`BeginHold` sets the ignore-until). Playback still stops if the sidecar is down; the transcript then takes the fallback below.

`IsEcho` is true when at least 60% of the heard words appear in the sentence being spoken. Echo of the playing line does not cancel playback. After the agent's speech ends, and after every spoken cue, a 1 s mute (`PostSpeechIgnoreMs`) blocks an idle Immediate start, and an Immediate start whose words pass `IsEcho` against the last spoken text within 3 s is ignored. That 1 s mute is **not** applied to a held PTT capture (it would eat the first second of a quick reply); the echo check still runs when the held text is posted. The accept cue still plays on post, then the mute. The sidecar's `SpeakToUser` enqueues (`Speak`); calls play in order on the selected voice (`speech_output_voice_id`). While a line is playing, a wake name or real speech stops it (see barge-in above); filler-only noise does not. In push to talk, pressing the key does.

The appended prompt block (`DysonAgentSystemPrompts.MetaAgentVoiceDirective`, root Meta Agent, voice on only) tells Meta: the user is speaking to a voice sidecar, not to you; you have no `SpeakToUser`; `MessageVoiceModeSidecar` sends the short version the sidecar speaks, and it returns at once; keep `PostConversationMessage` for names, paths, ids, and links; a message that starts with `[Message from voice sidecar]` is the sidecar speaking for the user, and it outranks the current plan the same way a mid-turn user comment does (that sentence is also on the directive line that names `[User comment during turn]`); speech never interrupts your turn. The model does not choose the input mode. Low latency speaks one job per sentence; reliable speaks the whole string as one job. The workdir prefix is unchanged and Meta must not add it.

### Voice Mode Meta Sidecar

One hidden sidecar per root Meta session (`DysonAgentModes.VoiceSidecar`, `"Voice Mode Meta Sidecar"`). It is not in `BuiltIns` or `ComposerSelectable`. `ValidateSubagentSpawn` rejects it with `Voice Mode Meta Sidecar is harness-created only.` It is not a registered child: no `SubSessions` entry, no agent id, not reachable by `ListMetaAgentDrones`, `DeleteMetaAgent`, or `MessageMetaAgentDrone`. The Meta session holds it on `VoiceSidecar`; the sidecar holds Meta on `VoiceSidecarOwner`. Its persisted row has `ParentSessionId` = the Meta persistence id, `RuntimeId` 0, and `MaxTargetContextTokens` 120000. Roster, restore, and recovery skip that mode (and `RuntimeId` below 1). Navigation and resume of a sidecar id are refused. Sidebar lists are roots only, and inactive delete skips the mode, so it never appears. Deleting the root cascades the row. The 100-cap chat trim applies only to a parentless Meta Agent, so the sidecar's own turns are not trimmed.

Creation is lazy. `DysonSessionRuntime.EnsureVoiceSidecarAsync` runs when voice turns on and when a root Meta session loads while voice is on. It returns the live sidecar, else loads the oldest sidecar child (extras are logged, not deleted), else creates one. Single-flight per Meta id. Voice-off sessions never get one. Nothing runs at startup. The first utterance after voice-on may wait for that one row load. An unset Meta Sidecar model inherits the Meta session's model and effort at creation. The sidecar's system prompt is `VoiceModeMetaSidecarDirective` (no shared preamble): speak first, pass work to Meta, do not do the work, do not poll. Non-empty private memory is appended as `Your memory (private notes, from ReadMemory):`.

Its catalog is exactly eight tools (`DysonVoiceSidecarTools.AllowedToolNames`), voice on or off: `SpeakToUser`, `MessageMetaSession`, `ReadMetaAgentLog`, `ReadMemory`, `EditMemory`, `ListWorkdirs`, `OpenWorkdirsPanel`, `SwitchWorkdir`. No file tools, no dispatch, no notes, no plans, no browser, no shell. `SpeakToUser` (at most 600 characters) queues TTS on the Meta session's work directory, so the workdir prefix still applies, and posts a `[spoken]` `DisplayInfo` line on the Meta chat. A Meta caller gets `SpeakToUser is only available to the voice sidecar. Use MessageVoiceModeSidecar.` `MessageMetaSession` and `MessageVoiceModeSidecar` publish `DysonVoiceSidecarMessageEvent` and return at once. The runtime subscribes the Meta scope once and the sidecar scope per sidecar id: a replaced or recreated sidecar gets its subscription moved to the new id, and runtime dispose disposes them all. Delivery is a per-target channel, in publish order, using the Callsign `RouteFor` table: inject into the in-flight turn, else a queued turn. Meta to sidecar never cancels the sidecar's turn. Sidecar to Meta never cancels Meta's turn. Injected text uses `[Message from Meta session]` or `[Message from voice sidecar]` (`DysonInjectedUserComments.MetaMarker` / `SidecarMarker`), then a blank line, delivered as a user message. A closed comment intake falls through to a queued turn. `ReadMetaAgentLog` takes `maxLines` only (default 80, clamped to 1–400) and returns status, busy, the turn in flight, recent log lines, and the last three chat posts cut to 1,000 characters. It does not return Meta's transcript. `ReadMemory` / `EditMemory` are the sidecar's private notes (see [sessions.md](../storage/sessions.md)).

Work-directory switching by voice: the sidecar calls `ListWorkdirs`, matches the spoken name itself (prompt guidance, no fuzzy-match code; it asks when two or none fit), speaks where it is going, then calls `SwitchWorkdir` and ends its turn. Voice input follows the screen: the next utterance reads `ActiveId` and goes to the new work directory's Meta and sidecar (created on navigation and on first use). The old sidecar and Meta stay live; anything they say later carries the workdir prefix. A background sidecar (its workdir not on screen) gets `NotOwnerMessage`; the prompt tells it not to retry.

The sidecar's context is pinned at 120K (`DysonMaxTargetContextTokens.VoiceSidecarFixed`). Compaction uses `DysonFullSummarizeFlow.SidecarInstruction`, which asks for a summary under 5,000 tokens. The harness does not trim that summary. A bus message that arrives while a summary runs is queued and still runs. The sidecar gets no Rethink turn on the tool-round budget, like Meta.

If the sidecar cannot be created, or its provider rejects the turn (other than a superseded or deferred prompt), that one utterance goes to the Meta session by the old route. The utterance is then Meta's user prompt (the one user bubble; no `[voice input]` display line was posted), plus one `DisplayInfo` line that the sidecar could not answer and the message went straight to the session. The next utterance tries the sidecar again. Voice is not turned off.

Turning voice off (`SetMetaVoiceModeAsync(null)`) calls `DysonSessionRuntime.DropVoiceTurnsOnVoiceOff` before `StopAsync(UserOff)`: every turn queued on a sidecar, every `[Message from voice sidecar]` turn queued on Meta, and unread inbox messages are dropped; a typed Meta prompt stays queued. An inbox delivery already in flight becomes a no-op (delivery generation).

`ApplyVoiceSidecarModelAsync` applies the Meta Sidecar model to every live sidecar and returns one error with each failure on its own line; one failure does not skip the rest. An injected sidecar or Meta comment keeps its marker on the reasoning-log segment, which persistence and compaction replay, so it is not lost after reload.

### Immediate and push to talk while the sidecar is busy

Once the Immediate pause expires, or a Push to talk hold ends with words, the utterance interrupts the sidecar's own running turn and is inserted at the head of the sidecar's prompt queue as a new turn (so it carries `VoiceSidecarTurnInstruction`). Partials never interrupt. The Meta session's running turn is not cancelled. `DysonUiHost.InterruptVoicePrompt` merges a second utterance with `message.Mode` (not a hard-coded Immediate), so a PTT follow-up stays Push to talk, and aims that interrupt at the sidecar.

`DysonSessionRuntime.InterruptWithPrompt` validates like `EnqueuePrompt`, rebuilds the queue with the new entry first, and cancels only the prompt that holds the gate (`_runningPromptCts`) on the session it was given. Gate-waiters are not cancelled. A run that ends because of that cancel returns `PromptSupersededError` (`"Prompt was interrupted by a newer voice message."`); the host maps that to success, so no caller shows an error or restores a typed draft. Cut-off tool calls get the existing paired stub `OpenAiCacheFriendlyTranscriptBuilder.IncompleteToolResultContent` (`"Tool call did not complete (cancelled or interrupted)."`). Drones and explores keep running; a `WaitForSubagent` in flight on Meta is not abandoned by speech. During `/summarize` or inline compaction the voice turn is queued and the summary is not cancelled.

A second Immediate or Push to talk utterance while the first voice turn is still queued is merged into it (`TryRemovePrompt` + `MergeUtterances`: one `InputPrefix`, then both texts). Once that turn has started, the second utterance interrupts it. Typed prompts already queued stay behind, in order. Before posting an interrupt, the runtime calls `DropPendingSpeech`, which drops lines the interrupted turn had queued (`ponytail:` the flush is global, so another work directory's queued lines drop too; upgrade is a per-work-directory epoch, not a small change while one channel and one speak loop serve every work directory). The speak loop re-checks the speak epoch right before playback, and again inside `DysonSpeechTryout.PlayPreparedAsync` after its thread hop, so a line already dequeued never starts after a barge-in or drop.

Turn-on checks (`Requirements`, first failure wins; each message points at Settings → Voice): an active speech-to-text model, an active text-to-speech model, exactly eight non-blank wake names (Callsign only; Immediate and Push to talk skip this), a trained voice when the active TTS is Qwen-family only (Python Qwen or Qwen GGUF; Pocket and Chatterbox speak with no clone), and not a CrispASR speech-to-text model (Phonon 2 GGUF, or Whisper tiny/base on CPU or Vulkan) together with any GGUF text-to-speech model (one CrispASR sidecar per process; they would evict each other). Whisper on Intel NPU is not that sidecar, so it can stay on with a GGUF voice. Immediate also requires Nemotron, as above. Push to talk does not.

Latency follows the STT update rate. Nemotron updates about every 560 ms, which is why the pause floor is 1 s. Phonon uses 2 s windows plus transcription, so a Callsign 3 s pause becomes about 3–5 s and barge-in reaction is about 2–3 s. There is no VAD. An update is entirely inside the first second after a Callsign wake or entirely eligible, judged only by its timestamp.

Every speech model, including Crisp GGUF TTS, does one inference job per sentence when `speech_response_mode` is `low-latency`, and one job of the full text when the mode is `reliable` or anything else.

Ceilings (`ponytail:` in the engine):

- Python TTS cancel fades audio in about 150 ms, but the bridge finishes the current request in the background (drain). The next utterance waits. That wait is worst in `reliable` response mode; `low-latency` sentence streaming shortens it. Upgrade: a bridge `op: cancel`.
- CrispASR cancel aborts the HTTP read. The server may finish that generation before the next request. The model stays loaded.
- The echo filter is a text heuristic, not acoustic echo cancellation. Echo of the sentence being spoken does not cancel playback. Upgrade: Windows voice-capture DSP in `DysonWindowsAudioCapture`.
- The live stream restarts after each submit and after 400 idle characters with no wake. A wake spoken in that roughly 100 ms gap is missed.

## Plan tools

Every executor call is scoped by `_workDirectoryId` (the session's work-directory Guid, not the live worktree path). `IDysonPlanRepository.GetAsync` / `UpdateAsync` / `DeleteAsync` look up `Id == planId && WorkDirectoryId == workDirectoryId`. A `planId` alone can never cross work directories. That is load-bearing: `planId` is a sequential `long` (globally unique across the table), so `4` is guessable in a way a Guid is not. `planId <= 0` is rejected with `DysonMetaAgentTools.PlanIdMustBePositiveMessage` before the query. Runtime mode checks (`MetaAgent` vs `MetaAgentDrone`) sit in the executor — the catalog is not the security boundary.

Meta plan bodies live in the `plans` table against that work directory, not as `.dyson/plans/*.md` on a drone branch. `SubmitPlan` is unchanged (Plan-mode only).

Who does what: a plan is **authored** by a plan drone (`purpose: plan`: explore, then `SubmitMetaPlan`). It is **revised** with `EditMetaPlan` by the authoring drone, a build drone that finds the plan wrong or outdated, or the root Meta Agent for small comment-driven fixes (substantive revisions are relayed to the authoring drone with `MessageMetaAgentDrone`). The root prompt, the drone directive and mandate, the `purpose: plan` brief, `DysonMetaBuildBrief`, the `Plan comments on metaplan:…` turn (`DysonFileViewerComments.FormatPrompt`), and the `SubmitMetaPlan` / `EditMetaPlan` catalog descriptions all say so; `DysonEditMetaPlanTests.Prompts_briefs_and_descriptions_name_EditMetaPlan` pins that each names the tool.

### `ListPlans` JSON contract

Returns an array of objects with **exactly** `planId`, `title`, `status`, `buildAgentId`, `updatedUtc`. **No `planRelativePath`, no `markdown`, no `note`.** `IDysonPlanRepository.ListAsync` already omits `Markdown`; the tool projection also drops `PlanRelativePath` and `Note`. `DysonPlanStatusTests.ListPlans_serialized_json_omits_path_and_markdown` locks the JSON property set. Widening the payload is a regression against prompt-cache stability and the no-filesystem rule (a path in the roster is a path the agent can try to use).

`status` is the enum name lowercased (`draft` / `building` / `completed` / `stale`). Archived plans are omitted (`ListAsync` default); there is no `includeArchived` argument, so the payload shape is unchanged.

### `SetPlanStatus`

Accepts `building` / `completed` / `stale` only (`DysonMetaAgentTools.SetPlanStatusAcceptedMessage`). `draft` cannot be set back. Optional `note`. Does not clear `BuildAgentId`.

### `BeginBuildPlan`

`DysonMetaBuildBrief.Build(planId, title, extraInstructions)` — names the `planId` and tells the drone to call `ReadMetaPlan`; **never inlines markdown**. Unrelated to `DysonBeginBuildPlanFlow` (Plan-mode layout-only turn of the same English name). `DysonBeginBuildPlanToolTests` asserts the layout-only Instruction is absent from the brief.

Reuse: `agentId` → `TriggerSubagentEventAsync` with that brief (not capped). Otherwise spawn one coordinator via the same `CreateMetaAgentDroneChildAsync` core (`useWorktree: true`, `purpose: build`); that spawn counts toward `MaxRunningWorktreeDrones`, and a refused spawn leaves the plan status unchanged. One plan is never split across several drones; the builder runs its own workers. Then `UpdateAsync(..., status: Building, buildAgentId: persistenceId)`.

Optional `modelSlug` and `reasoningEffort` apply only on that new spawn. Omit, missing, or whitespace is null/null (Settings Meta Agent Drone default, including its effort; the parent only if that default is unset). Slug set and effort omitted uses that slug's defaultEffort. Effort set and slug omitted keeps the settings model with that effort. Both set uses both strings. `agentId` reuse ignores both and does not change the existing drone's model.

Second builder: `FindLiveBuilder` refuses a new spawn while a **non-terminal** child still matches `BuildAgentId` (`"Plan {id} is already being built by agent #{n}. Pass that agentId to extend the build, or SetPlanStatus stale first."`). A `Building` row whose builder is already terminal can start a new one. That is the live-builder check, not a `Status == Building` check.

### `DeletePlan`

Archives the plan (`IDysonPlanRepository.ArchiveAsync`): sets `ArchivedUtc`, keeps the row and its `Status`. Success JSON `{ ok: true, planId, archived: true }`; log `DeletePlan #{planId} archived: {reason}`; publishes `DysonPlansChangedEvent`. Already archived is a success that keeps the original `ArchivedUtc`. The user restores from the **Archived** section of the plans column; there is no `RestorePlan` tool. Archived plans refuse `UpdateAsync` (`SetPlanStatus`, `EditMetaPlan`, `SubmitMetaPlan` revise) and `BeginBuildPlan` (checked before any spawn). `ReadMetaPlan` still works. See [plans.md](../storage/plans.md#archive).

Refuses while `Status == Building` (`"Call SetPlanStatus with stale, or stop the builder first."`). Status is the gate; `BuildAgentId` is not consulted.

### `SubmitMetaPlan` (drone-only) / `ReadMetaPlan` (every mode) / `EditMetaPlan` (root and drone)

`SubmitMetaPlan` inserts `Kind = MetaPlan`, `Status = Draft`, or overwrites `Title`/`Markdown` of the **existing row in place** when `planId` is given (`UpdateAsync` on the same id; it never creates a second row, and a cross-workdir id is not found). Its description tells the model to prefer `EditMetaPlan` for revisions and to create large plans from a short skeleton. Returns `{planId, title, status}`. Writes **no file**. Cross-workdir `planId` is `"Plan '{id}' not found."`. Empty markdown is a Result error. After a successful create or revise (and after `SetPlanStatus` / `BeginBuildPlan` / `DeletePlan` succeed), the executor publishes `DysonPlansChangedEvent` on `DysonBusScopes.WorkDirectory` so an already-open meta page can refresh `MetaPlanList` without a reload.

It is **not** a report: no `EndsCurrentTurn`, does not call `SubmitSubagentReportAsync`, does not enqueue a parent interrupt. The drone must still `SubmitSubagentReport`. A plan-authoring drone that stops after `SubmitMetaPlan` is caught by the existing unfinished-work / child-report watch. Covered by `DysonSubmitMetaPlanTests`.

`ReadMetaPlan` returns `{planId, title, markdown, status}` for a row in **this** work directory. It is on the default catalog (`DysonMcpPipeline.CreateDefault`, one `DysonMetaAgentTools.CreateReadMetaPlanTool()` definition), so every mode can read a plan by id (Ask, Plan, Work, Explore, Drone, reviews, custom modes); the root Meta Agent and drones keep it via their allowlists. `EditMetaPlan` and `SubmitMetaPlan` stay meta-only. A classic Drone worker inside a meta-drone worktree reads the same rows (the work-directory id is the parent's). The `markdown` string is exactly what `EditMetaPlan` matches `old_text` against (no line-number prefixes, stored EOLs kept). The success result is exempt from the 64KiB `DysonToolResultLimits` clip, so the full body is returned with no character cap and no paging. A body too large for the context window surfaces as a provider error, with no silent slice. A large plan read counts toward the live context like any tool result, so it can trip [context compaction](README.md#context-compaction) after that round's tools finish.

`EditMetaPlan` edits an existing plan in place, mirroring `WriteFile` with `planId` in place of `path`:

```json
{ "planId": 49,
  "old_text": "...", "new_text": "...", "replace_all": false,
  "edits": [ { "old_text": "...", "new_text": "...", "replace_all": false } ],
  "content": "...",
  "title": "optional rename", "summary": "optional revision note" }
```

- Exactly one of `content`, `old_text`+`new_text`, or `edits[]` per call; a mixture is rejected (`exactly one of`). `title` alone renames. Unlike `WriteFile`, `old_text` plus `edits[]` is rejected instead of concatenated, items in `edits[]` missing a string `old_text`/`new_text` are an error instead of skipped, and there is no `path`.
- Edits run through `DysonTextEditApplier.TryApplyEdits`, the same ordered all-or-nothing applier `WriteFile` and `UpdateNote` use: each edit sees the previous edit's result, `old_text` must match exactly once unless `replace_all`, and the first failure aborts with `edits[i]` and the match count (`old_text` for the single form). Nothing is written on failure (`Plan {id} is unchanged`).
- Persistence is `UpdateAsync` on the same row: `Markdown` (and `Title` when given) change, `UpdatedUtc` bumps, `Status` / `Note` / `BuildAgentId` are untouched. There is no revision counter or history column, so none is returned. `DysonPlansChangedEvent` is published once on success. An open `FileViewerOverlay` keeps the text it loaded; only `MetaPlanList` refreshes.
- Same-stage calls run concurrently, so read-modify-write runs under a per-`planId` gate (static dictionary in `DysonWorkspaceToolExecutor`, shared with `SubmitMetaPlan` revisions): two edits to one plan compose. The catalog description still asks for at most one call per plan per stage, with multiple hunks in `edits[]`.
- Result: `{planId, title, status, updatedUtc, mode, edits:[{index, replacements}], chars, lines}`. Errors are `Result` text: unknown or foreign `planId` (`Plan '{id}' not found.`), mixed modes, bad edit shape, not-found / ambiguous, or the repository's non-empty-`Markdown` rule.
- Review comments: `FileViewerOverlay` comments hold no stored anchor (an excerpt of the clicked block plus text, in memory until sent as a turn), so an edit cannot break one. See [plans.md](../storage/plans.md).

A `SubmitMetaPlan` / `EditMetaPlan` argument that is not valid JSON returns `"{tool}: invalid JSON arguments: {parser reason + position} ({n} chars received[, and they do not end with '}' ...]). Send a smaller payload ..."` pointing at `EditMetaPlan`. Provider adapters parse arguments once (`OpenAiCompatibleHttp.SplitStageFromArguments`); a malformed (not cut off) body still reaches the executor as raw text, still containing `"stage"`. A body that is truncated because the model's stream ended early or hit its output limit never gets that far: the adapter marks the call (`DysonToolCall.ArgumentsError`) and the scheduler returns `"{tool}: the call was not run. Its arguments were cut off at N chars because …. Submit a short skeleton with SubmitMetaPlan, then grow it with EditMetaPlan edits[]"`. See the cut-off rounds note in [README](README.md).

### Status vs `BuildAgentId`

- **`Status` is authoritative for "is this building"** on the page and for `DeletePlan`. The UI spinner and the Build button both key off `Status` only (`MetaPlanList`: `BuildAgentId` can linger after a build ends). Clicking a plan opens `FileViewerOverlay` with display path `metaplan:{planId}/{slug}.md` from `GetAsync` (no disk). **Build** sends a session message; the Meta Agent calls `BeginBuildPlan` itself.
- **`BuildAgentId` is history.** It is set when a build starts and is **not cleared on completion** (`IDysonPlanRepository.UpdateAsync` cannot null it — null means leave unchanged). Do not treat a leftover id as "still building".

## Child-report watch (all parents)

Not Meta-Agent-only. A child that goes terminal without `SubmitSubagentReport` would otherwise leave every parent idle forever (Meta Agent never polls; Work `WaitForSubagent` would sit until timeout). `DysonChildReportWatch.Evaluate` is a pure function (`DysonChildReportWatchTests`):

| Inputs | Action |
| ------ | ------ |
| not a child / already `Completed` or `Failed` / pending or in-flight work | `None` |
| `Active`, idle, unreported, `remindersSent < 2` | `Remind` — enqueue `ChildReportReminder` (kind 19) on the **child** |
| `Active`, idle, unreported, reminders spent | `Synthesize` — child becomes `Failed` |
| `Stopped` / `Interrupted` / `Failed` without a report | `Synthesize` immediately |

`remindersSent` (`_childReportRemindersSent`) and `LastReportSummary` are **in-memory, per-process**. They are not session columns. After a restart the counter is gone. A restored `Stopped` child counts as already reported (Stop synthesized at stop time): `RestoreFromPersisted` restores `LastReportSummary` from its last `SessionStatusChanged(Stopped)` reason, so the watch does not re-report it as `application restart`.

### Synthetic report

`DysonAgentSession.SubmitSyntheticReportAsync` calls `SubmitSubagentReportAsync(..., failed: true, bypassIncompleteTodos: true, allowStoppedOrInterrupted: true)`. Same pipeline: `TryAcceptSubagentReport` → `NotifySubagentFailed` → `EnqueueInterrupt` → host `SubagentReportProcessing`. Idempotency is the existing "already submitted" guard (`_subagentReportAccepted`), not a second counter.

`KickOffChildPrompt` synthesizes on provider/exception failure; after a successful turn with nothing queued it runs `ApplyChildReportWatchAsync`.

### Stop semantics

A user halt (`DysonUiHost.StopAllExecution`) and `StopSubagent` / `StopMetaAgentDrone` mark the child **`Stopped`**, then synthesize.

`TryAcceptSubagentReport(..., allowStoppedOrInterrupted: true)` **keeps** `Stopped` (and `Interrupted`). A deliberate halt is not rewritten to `Failed`. The parent still receives `SubagentFailed` — that interrupt means **"this child is done and will not report"**, not "the work failed". `ListMetaAgentDrones` and the UI cards read `Status`, which stays `Stopped`. Covered by `DysonSyntheticReportTests`.

The widened guard is harness-only. An agent's own second `SubmitSubagentReport` still rejects (`"session already Stopped"`). A second synthetic also rejects (Stop + cancelled-run KickOff both reach the same stop; the parent must be told once).

Idle-without-report after two reminders **does** set `Failed` — that child was still `Active`.

Stop cancels whatever run is live. KickOff runs carry a run CTS; a child turn the host runs (report processing, queued continuation) gets a linked CTS attached in `OpenAiCompatibleAgentSession.PromptWithTurnAsync` (and the same in `DemoDysonAgentSession`), so `HasActiveBackgroundRun` is true and `CancelBackgroundRun` reaches it. A drone resumed after a restart is `Active` again (inject / BeginBuildPlan reuse reopens `Interrupted`), so `TryMarkTerminal(Stopped)` succeeds instead of returning the stale `Interrupted` / `application restart`.

One provider loop per session. `KickOffChildPrompt` and `DysonSessionRuntime.ExecutePromptAsync` take the same per-session gate (`DysonAgentSession.EnterPromptGateAsync`). An interrupt cancels the live run first and the new KickOff waits for it to unwind inside its own task. `ExecutePromptAsync` returns `PromptDeferredError` while `HasActiveBackgroundRun`, checked again after both gates are held. The host-owned `DysonUiHost.ExecutePromptOnSessionAsync` path makes the same check and takes the same session gate. A deferred prompt is never an error: `DysonUiHost.DrainAutoTurnsAsync` puts the report / event back at the head of its queue (`RequeueAtHead`), and `PromptHarnessTurnOnSessionAsync` (queue drain, composer, question answer, summarize, voice) puts the turn back at the head of the prompt queue (`RequeueUntilBackgroundRunIdle`, `EnqueuePrompt(..., atHead: true)`). Both retry once `WaitForBackgroundRunIdleAsync` completes. A parent message whose KickOff is interrupted before its prompt starts goes back to the head of `_pendingTurns`, so the newer message runs first and the older one still runs. The transcript builder treats every turn on the in-flight stack (`InFlightPromptTurns`) as incomplete, so overlapping loops cannot replay the same `tool_use` ids twice.

### Recovery

`DysonSessionRecoveryService` has no live session graph. For each Active descendant it marks `Interrupted` and appends one parent `Interrupt` log (`SubagentFailed`, summary `application restart`, child's `RuntimeId` / persistence id) via `PersistSyntheticParentReportAsync`. Idempotent if that log already exists. It does **not** call `SubmitSyntheticReportAsync` (nothing is in memory to accept a report). It does not replay model or tool calls. A persisted reminder counter would never be read: Interrupted descendants synthesize immediately on this path. `Stopped` / `Completed` / `Failed` descendants are skipped: their status and last report are unchanged.

## Context: 180K cap, compaction, reasoning

**180K is not configurable** for Meta Agent: `ResolveEffectiveMaxTargetContextTokens` returns `DysonMaxTargetContextTokens.MetaAgentFixed` (180_000) and ignores session/slug overrides including `0 = Off`. `DysonUiHost.SetSessionMaxTargetContextTokensAsync` rejects with `"Meta Agent context is fixed at 180K."`. Composer hides the ± stepper when `SelectedAgentMode` is Meta Agent (`ContextLimitLocked`). Meta Agent Drones keep the normal cascade (harness default 200K). The voice sidecar is pinned at 120K (`VoiceSidecarFixed`, 120_000) the same way, and its compaction instruction targets 5,000 tokens. Covered by `DysonMetaAgentContextCapTests`.

**Chat window: newest 100 interactions.** `DysonMetaChatWindow` (Engine, `Session/`) caps a root Meta Agent chat (`ParentSessionId` null, mode Meta Agent) at `MaxInteractions` = 100. One interaction is one bubble `MetaChatItems.Build` emits: a `Normal` turn with instruction text, an image, or a hidden attachment block; each non-blank injected `UserComment`; a `DisplayInfo` turn with assistant text. `DisplayStart` walks backward to the turn where the newest 100 begin, and the projection starts there, so a re-render never re-projects the whole history. Queued prompts follow outside the cap. On load, `RestoreFromPersisted` drops the turns `SelectTrimmable` picks from memory and hard-deletes them (`DeleteTurnsAsync`, plus their turn-scoped `session_logs` rows) on a `Task.Run`, off the circuit. A turn can be deleted only when it is all of these: before the display window, before the latest successful `FullSummarize`, already `IsExcludedFromContext`, completed, not an unanswered question card, and not the source of a visualization a shown bubble opens. The summary and every later turn stay, because the model context still needs them. With no compaction yet, nothing is deleted. Trimming is idempotent, and a failed delete is logged and retried on the next load. Todos, plans, scratch files, notes, and child sessions are separate tables and are never touched. The old 15-turn maintenance tick (`DysonMetaMaintenanceTick`) stays removed. Old `MetaMaintenance` (kind 18) rows still load and render. When the live context passes 180K, Meta Agent takes the same [context compaction](README.md#context-compaction) path as every other mode: pause at a safe point, inline `FullSummarize`, then a queued `Continuation` (a turn that finishes over the limit is summarized at turn end with no Continuation; a pending trip on `sessions.CompactionPendingTurnId` is summarized before the next prompt). The directive's Context lines say so ("Context is summarized automatically when it passes the limit.") and tell the agent to call `CompactConversation` whenever the thread drifts. The scratch-notes lines say older turns get summarized away and notes are the durable copy.

**Reasoning always preserved.** Meta Agent skips the `preserve_reasoning_traces` read and always replays stored reasoning items for finished turns from the same provider source (see the reasoning rule in [README.md](README.md)#openai-compatible-provider). Meta Agent Drones follow the setting.

**Tool-history compaction** (`tool_history_compaction`) applies to Meta Agent like every other mode: off unless the setting is `"true"`.

**Provider conversion.** A Meta session on a Demo slug converts to an OpenAI-compatible slug like any session: pick the slug in the composer `ModelSlugPicker`, confirm, and `DysonUiHost.ConvertSessionToSlugAsync` reloads the same session id (so `FindExistingMetaAgentSessionAsync` still binds it). Refused while busy. Children keep their slug. See [sessions.md](../storage/sessions.md#resume).

## Traps

- `ListPlans` JSON is a closed property set. Adding `markdown` / `path` / `note` / a prune `notice` is a contract break (`DysonPlanStatusTests`).
- `LoadSkill` with a file path in Meta Agent mode is the silent hole; the Literal post-filter is the whole no-filesystem design (`DysonMetaAgentLoadSkillTests`).
- `SubmitMetaPlan` is not a report. A drone that returns after it leaves the parent waiting until the child-report watch fires. Neither is `EditMetaPlan`.
- Resubmitting a whole large plan to revise it is the failure mode `EditMetaPlan` exists to avoid: one malformed or cut-off JSON argument loses the entire revision.
- `BuildAgentId` lingering after a completed/stale plan is expected. UI and `DeletePlan` use `Status`.
- Sequential `planId`s are guessable; always pass `_workDirectoryId`.
- `ReadMetaAgentDroneLog` / reminder counts / `LastReportSummary` die with the process. The child **session** row rehydrates; the log lines do not.
- `SubagentFailed` after a user Stop is a closed loop, not a failed build. Read `Status`.
- `useWorktree: false` without `existingWorktreePath` shares the parent checkout and must not switch branches. `existingWorktreePath` (only with false) rebinds to an already-listed worktree and that drone does not merge on completion. Several `useWorktree: true` drones are several merges; related changes go through one coordinator ([Dispatch shapes](#dispatch-shapes-coordinator-vs-parallel-direct)). A failed report that starts with `Merge conflict.` is the resolve note, not a dead task: spawn the resolver, do not stop the conflicted drone, and do not edit files.
- `IDysonPlanRepository.UpdateAsync` cannot null `Note` / `BuildAgentId`. `DysonPlanKind.ClassicPlan = 0` is reserved; every row today is `MetaPlan`.
