# UI

Landing project: [`src/Harness/Harness.UI`](../../src/Harness/Harness.UI) — Blazor Interactive Server (`net10.0-windows` on Windows, else `net10.0`), references `Harness.Engine` and (Windows only) `Harness.WindowsBrowser`. Shared host builder: `DysonUiWebHost` / `DysonUiWebHostOptions`. `DysonUiHost` is a hook, not a second engine — see [rules/rules_engine_ui.md](../../rules/rules_engine_ui.md).

## How to run

From repo root:

**Windows desktop shell (CefSharp):**

```bash
dotnet run --project src/Harness/DysonHarness.UI.Windows
```

**Browser-based Blazor (all platforms):**

```bash
dotnet run --project src/Harness/Harness.UI --urls http://localhost:5180
```

Or open the solution and set **DysonHarness.UI.Windows** (Windows) or **Harness.UI** as the startup project. The app uses Interactive Server rendering globally.

DI: `AddDysonHosting` + `AddDysonLocalDb` (registers `IDyson*Repository` / `DysonDbContext` factory), scoped `DysonToolPolicyStore`, `DysonPluginCatalogService`, `IDysonPluginPackageService`, `DysonPluginLifecycleService`, protected-variable and hook-review services, `ThemeService`, `HttpClient` (via `IHttpClientFactory`), `ManagedInferenceProviderCatalog`, `DysonUiHost`; singleton `DysonSessionRuntimeRegistry` + `IDysonSessionRuntimeScopeFactory` (`DysonUiSessionRuntimeScopeFactory`); scoped `DysonUiRuntimeAttachment`, `IDysonAgentSessionRuntimeFactory` (`DysonUiAgentSessionRuntimeFactory`), `DysonUiAgentSessionRuntimeConfigBuilder`, and `DysonSessionRuntime` (resolved inside the retained subject scope, not the Blazor circuit); singleton `DysonPluginContributionResolver`, `DysonPluginPackageLimits`, and `IDysonPluginPackageParser`. Singletons also include `DysonCliProxyHost` (disposed on app shutdown) and `DysonAppUpdateService`. The registry is disposed on `ApplicationStopping`.

**Windows only:** `DysonUiWebHost` also registers `AddSingleton<IDysonBrowserControl, DysonCefBrowserControl>()`. `DysonUiHost` injects that singleton into every `DysonAgentSessionConfig.BrowserControl` (new + resume) and subscribes to `SnipCaptured` so browser chrome snips become pending composer images. When set, the engine MCP catalog includes browser tools (`OpenBrowser`, …) that open in-process CefSharp WPF windows. Continuous **win-x64** zips ship `DysonHarness.exe` from `DysonHarness.UI.Windows` — see [packaging/webview](../packaging/webview.md) and [releases](../packaging/releases.md).

On first open, a default **Demo Mock** provider + slug is seeded if none exists. SQLite lives under the platform app-data folder for the current `DysonAppMode` (see [storage/models](../storage/models.md)).

`DysonUiHost` branches on effective `ProviderKind` (see below): `demo` (no credentials) → `DemoDysonAgentSession`; `OpenAICompatible` → `OpenAiCompatibleAgentSession` (engine). Anthropic is not wired yet. OpenAI-compatible sessions expose in-process web search MCP tools (`FreeSearch`, `WebFetch`, …) via the engine catalog — see [engine README](../engine/README.md)#web-search--fetch-in-process. Web tools summarize **inside** the executor (`DysonWebSearchSummarizer`); optional summarizer slug from Settings → General (empty ⇒ session model via `SummarizerProvider` null). Assert coverage for search SSRF, session todos, file manager, PlanResult, Plan shell warning, long-running shells, and UI helpers lives in `Harness.Tests` (`dotnet test src/Harness/Harness.Tests/Harness.Tests.csproj`) — not UI startup.

**Provider routing:** session type follows the slug’s provider `ProviderKind`. Demo mode is for offline UI testing — `DemoDysonAgentSession` injects mock tools every turn (`read_file`, `grep`, `list_dir`) and mocks `RenameSession` only on rename-review turns (1, 9, 17, …), without calling an LLM. OpenAI-compatible providers call the real API and only run tools the model requests.

**Mis-tagged providers:** if a row has `ProviderKind = demo` but a Base URL or API key is set, create/save in **Settings → Models** coerces it to `OpenAICompatible`, and `ResolveProviderAsync` treats it as OpenAI-compatible at session start even before repair. Use **Repair mis-tagged providers** on the Models settings page for a one-shot DB fix of existing rows (does not run on startup; leaves **Demo Mock** unchanged).

## Chat markdown links

All absolute `http://` / `https://` links in chat turn markdown (assistant body, user prompt, harness instruction) and in the file/skill viewer markdown open in the **OS default browser**, not inside the Blazor/WebView host. `DysonUiHost.OpenUrlInDefaultBrowser` allows only http(s); `wwwroot/chat-external-links.js` (loaded from `App.razor`) intercepts clicks under `.turn-block__body`, `.turn-block__user-prompt`, `.turn-block__instruction`, and `.file-viewer-modal__markdown`. In-app routes (e.g. settings `<a href="/settings/…">`) are left alone.

## Plugin import

Composer slash **`/plugins`** opens `PluginModal` and clears the command/remainder without starting inference, including when ordinary composer attachments are pending. The modal currently has one **Import** tab:

1. Choose one source: browser-uploaded ZIP, host-native folder, or GitHub `owner/repo` / HTTPS URL with optional ref and plugin subdirectory. ZIP size is checked before buffering; local folders are copied to staging. GitHub refs are resolved to an immutable commit.
2. **Preview import** validates the staged package and shows format, identity/version/schema, source/commit/checksum, components, executable/network/hook/variable capabilities, unsupported items, and diagnostics. Preview/install never execute hooks, scripts, skill resources, commands, or stdio MCP.
3. Choose exactly one unselected scope: **Install for this project** (disabled without an active work directory) or **Install globally** (current app mode/user). Exact package and `PLUGIN_DATA` destinations are displayed.
4. Acknowledge the capability review, then install. Back returns to the retained preview without reacquiring the source. Multi-package Cursor repositories expose an inline subdirectory picker.

Installed packages contribute only through the effective global + active-project catalog. Skills enter the skill catalog/`LoadSkill`; always-apply rules enter the bounded session prompt; custom agents are explicit choices; `/plugin-{plugin}-{command}` selection inserts editable instructions rather than sending them automatically. The import UI does not mutate `openrules.json` or create `.dyson/mcp` files.

**Installed-plugin management:** **Settings → Plugins** lists the effective global + active-project catalog, retains shadowed global installations for inspection, and displays scope, source, version, capabilities, component inventory, diagnostics, and lifecycle status. It supports enable/disable and explicit uninstall with an independent retain/delete `PLUGIN_DATA` choice. Declared variables use the protected value service and only show `[SET]`/`[NOT SET]`, never plaintext. Hook review status and its constrained review controls are shown per supported hook; updates remain unavailable because no safe update lifecycle API exists. Plugin MCP activation remains default-deny and has no management UI. OpenAI `.app.json` components are shown as unsupported.

Facts: `ComposerSlashCommandsTests`, `PluginImportControllerTests`, `DysonPluginPackageTests`, `DysonPluginCatalogLifecycleTests`, `DysonPluginContributionResolverTests`, `DysonPluginMcpTests`, `DysonPluginSecurityTests`.

## Skill search

Composer slash **`/help`** opens `ComposerHelpModal` (built-in commands + pattern templates; Insert fills the composer; no inference).

Composer slash **`/summarize`** compresses all eligible turns before the last **2** via `Host.SummarizeTurnsAsync` (skips already summarized / dropped / in-flight; claims one turn at a time so only the active turn shows Summarizing…; session single-flight with MCP). While any turn is summarizing, user Send enqueues (composer stays enabled — not full `IsBusy`); queue drains when summarization finishes.

Composer slash **`/summarize-full`** queues a **Full summary** turn via `Host.PromptFullSummarizeAsync` (requires a focused session with at least one turn). The model writes one handoff (≤ 6,000 characters); after success earlier turns are dropped (`IsExcludedFromContext`) and omitted from later transcripts. If the session is busy or mid-`/summarize` worker, the turn is enqueued like other prompts. Distinct from `/summarize` (keep-last-2 worker). Prefix `/sum` still lists `/summarize`; `/summarize-f` / `/summarize-full` resolve to the new command.

Composer slash **`/skill-search`** (built-in, matched **before** the `/skill-` local catalog filter) opens `SkillSearchModal`.

- **Provider tabs:** `IDysonSkillExplorer.ListProviders()` drives the tab strip (registration order in `Program.cs`; no UI re-sort). Every search / preview / download call passes the active tab’s `providerName` into the explorer; `DysonSkillExplorer` routes case-insensitively to the registered `IDysonSkillExplorerProvider` (unknown name → clear error).
- **Tab order / providers:**
  1. **SkillsHub** (`skillshub`) — `https://skillshub.wtf/` search/browse; preview via `/{owner}/{repo}/{skill}?format=md`.
  2. **skills.sh** (`skillssh`) — `https://skills.sh/` unauthenticated `GET /api/search` (empty query → empty page until the user types).
  3. **ClawHub** (`clawhub`) — `https://clawhub.ai/` search or trending list; preview `SKILL.md` via skills file API.
  4. **Skills Directory** (`skillsdirectory`) — public registry search (`GET /api/registry`), not the paid `/api/v1/*` key API.
- **Row actions (option C):** each result has **View skill file** and **Download**. View previews remote `SKILL.md` in `FileViewerOverlay` via `Host.OpenFileViewerContent` (display path like `{provider}:{slug}/SKILL.md`; no disk path) with footer CTA **Download skill**. Row **Download** installs immediately (per-row spinner). Download requires an active work directory. When ClawHub returns an ambiguous bare slug (`HTTP 409` / `AMBIGUOUS_SKILL_SLUG`), the modal expands that row with an inline publisher picker (label + View/Download) instead of dumping the error JSON; choosing a match retries with `ownerHandle/slug`.
- **Install package (per provider)** → `{activeWorkRoot}/.dyson/skills/{safeSlug}/` (slugs with `/` become filesystem-safe via `/` → `-`; overwrite same slug; strip a single top-level zip folder when present so `SKILL.md` sits at the skill root):
  - **SkillsHub** — markdown-only: write preview `SKILL.md` (no site zip).
  - **skills.sh** — GitHub zipball for `source` (`owner/repo`) filtered to the skill folder (`skillId`).
  - **ClawHub** — site `GET /api/v1/download?slug=` (plus `ownerHandle=` when known); ZIP extracts like Skills Directory, or JSON `public-github` handoff → fetch that GitHub zip and extract. Browse/search prefer composite `owner/slug` when the API returns an owner. Ambiguous bare slugs surface as structured matches (not a raw 409 banner). Respects `429` / `Retry-After` with a clear error (no aggressive retries).
  - **Skills Directory** — `GET https://www.skillsdirectory.com/api/skills/{slug}/download` → zip → extract.
  Installed skills are then available to `LoadSkill` / `/skill-` like any other `.dyson/skills` entry — see [work-directories](../storage/work-directories.md). After a successful install, the modal calls `Host.NotifySkillCatalogChanged()` so Composer refreshes its `/skill-` overlay cache without waiting for the next host change.

Engine types: `IDysonSkillExplorer`, `SkillsHubSkillExplorerProvider`, `SkillsShSkillExplorerProvider`, `ClawHubSkillExplorerProvider`, `SkillsDirectorySkillExplorerProvider`. Facts: `ComposerSlashCommandsTests`, `DysonSkillExplorerTests`.

## Theming

- CSS variables with `data-theme` (light/dark) and `data-accent` (Blue / Green / Red / Purple)
- Persist preference in subject `app_settings` (`ui_theme` / `ui_accent`). `theme.js` + `localStorage` (`dyson-theme`) remain same-session cache / DOM apply (Windows CEF chrome still reads `dysonTheme.get()`). `ThemeService.InitializeAsync` restores DB first, falls back to `dysonTheme.get`, and write-through-migrates valid localStorage values when the DB keys are empty.
- Visual direction: dense IDE geometry (unchanged padding, gaps, grid) with softer product materials — accent-tinted chrome (`--surface-chrome`), glass panels (`--surface-glass` + `backdrop-filter` when supported), theme-aware elevation (`--shadow-1..3` / `--overlay`), and 6–12px radii. Motion is color/opacity/shadow only (`--motion` / `--ease`); `prefers-reduced-motion` disables it.
- Shared tokens also include `--accent-border`, `--accent-glow`, `--focus-ring`, `--text-on-accent`, and aliases `--muted` → `--text-muted`, `--ok` → `--success`. Semantic git colors (`--git-modified`, `--success`, `--danger`) stay independent of the selected accent. Default blue accent remains `#4c8bf5` so `DysonUiThemeSnapshot` stays stable.

`ThemeService` + `ThemeSwitcher` own the applied attributes (General settings page). `ThemeService` captures live DOM (`dysonTheme.getResolved`) into an engine `DysonUiThemeSnapshot` (`light`/`dark` plus normalized lowercase `#rrggbb`; invalid or unavailable JS data falls back to dark / `#4c8bf5`) at create/resume, on theme/accent change, and at each host `PromptAsync`. Each turn rewrites only the `RenderHtmlVisualization` description from `Config.UiTheme`. Same values ⇒ identical tools JSON ⇒ the prompt-cache prefix survives (`SystemPromptGeneration` is not bumped). Children share config and interpolate their own pipeline at turn start. Already-rendered visualization iframes are not restyled.

## HTML visualizations

Successful built-in `RenderHtmlVisualization` calls attach a typed payload to their calling tool result. `TurnVisualizations` renders each successful payload inline in the calling turn, independently of the tool diagnostic row. The active session also shows a **Visualizations** bar when it has results; opening it displays a modal list of all visualizations, selects the newest by default, and renders only the selected item at large size. Duplicate titles are distinguished by turn time and a short visualization id.

The source is never injected into the parent Blazor DOM or enabled in chat Markdown. Every preview uses an iframe with `sandbox="allow-scripts"` and `referrerpolicy="no-referrer"`. Its `srcdoc` wrapper HTML-encodes the title, base64-wraps CSS and JavaScript before installing them, and applies a restrictive CSP: `default-src 'none'`, no network connections or external assets, no forms, objects, nested frames, base URI, popups, downloads, top navigation, filesystem access, browser storage, or parent-page access. Only self-contained browser APIs, inline SVG/Canvas, and data/blob media are suitable. This UI support is limited to Dyson's built-in visualization tool; custom/external MCP servers do not have a custom rich-result rendering protocol.

## Demo host (`DysonUiHost`)

- **Subject runtime (process-retained):** `DysonSessionRuntimeRegistry` keeps one `DysonSessionRuntime` per subject for the life of the process. Circuit disconnect and `DysonUiHost` / `DysonUiRuntimeAttachment` dispose **detach only** — they unsubscribe `Changed` and do not cancel prompts, discard runtime prompt queues, dispose the runtime, or run recovery. A later circuit for the same subject reattaches the same runtime object. App shutdown disposes the registry (cancels in-flight work and flushes persistence).
- **Circuit attachment:** Home `OnInitializedAsync` calls `Host.EnsureRuntimeAttachedAsync()` → `DysonUiRuntimeAttachment.AttachAsync` for the current `IDysonSubjectContext` (registry-normalized). Repeated attach is idempotent. The attachment is circuit-scoped; it is not the session owner.
- **UI focus is circuit-local:** `ActiveSessionId` / `Session` live on the scoped host. The runtime holds the live session graph and busy/queue bits but does **not** store which session a circuit is looking at. A reconnecting circuit must re-focus (list / click / resume); it does not inherit another circuit’s focus. Switching focus (`StartNewSessionAsync` / `ResumeSessionAsync` / `FocusSession`) does not cancel the previous session’s in-flight prompt. `Host.IsBusy` is the focused session only; `IsSessionBusy(Guid)` is the per-session bit used by the list spinner.
- **Demo factory limitation:** retained-scope `DysonUiAgentSessionRuntimeFactory` create/load support **demo** sessions only. OpenAI-compatible create/resume return explicit Result errors (`cannot create` / `cannot load OpenAI-compatible sessions yet`) and stay on `DysonUiHost`’s existing OpenAI path. The non-UI config builder takes an immutable theme snapshot and does not resolve `ThemeService`, browser control, Razor, or JS.
- **Process-restart recovery:** first registry attach after a new process runs `DysonSessionRecoveryService` (finalize unfinished turns; mark Active descendants `Interrupted`; no model/tool replay). Circuit disconnect does not run that sweep. Details: [sessions.md](../storage/sessions.md)#process-restart-recovery.
- **Live session registry:** host `_sessionsById` keeps parent + children for UI navigation and host-owned (including OpenAI) sessions while the circuit focuses one (`ActiveSessionId` / `Session`). Switching focus does not dispose other host entries. Demo sessions adopted by the runtime are retained on the subject runtime independently of the circuit.
- **Navigate:** `NavigateToSessionAsync(Guid)` / `NavigateToParentAsync()` — focus live registry entry or load from DB; sidebar stays **roots only** (children via cards / back, not listed).
- **Subagent cards:** `GetSubagentCardState(persistenceId)` → title, `RuntimeId` (child session id for muted `#id` on the card), `ModelLabel` (child `Provider`, else parent), latest turn `AgentTitle`, `IsRunning` / status for `SubagentCard`.
- **Auto-turn on report:** on parent `SubagentCompleted` / `SubagentFailed` / `SubagentStopped` interrupt, enqueue a harness `SubagentReportProcessing` turn for that parent; when parent `!IsBusy` and **not** in Plan mode, FIFO `PromptSubagentReportProcessingAsync` (`# Subagent report` mandate + bold **Report** block; analyze then continue in one turn — does not cancel in-flight parent work). Kickoff failures also surface a concrete reason here. In **Plan** mode, completions are buffered (UI still updates); **Build plan** folds them into the BeginBuildPlan Instruction (one `#` title + bold labels; reply still mandates `` ## Recap `` / `` ## Agent actions ``), or leaving Plan without Build drains them as `SubagentReportProcessing` auto-turns. `SubagentEvent` / Ask UI are not deferred.
- **Auto-turn on shell exit:** on `LongRunningShellExited` (from `SubscribeToLongRunningShellCompletion`), always FIFO-drain a `ShellExited` harness turn via `PromptShellExitedAsync` (auto-read tail in Instruction; trimmed after the turn completes — including while Plan). Does not cancel in-flight parent work.
- **Subagent events:** on `SubagentEvent`, show `SubagentEventBlock`; general kinds FIFO-auto-prompt `RespondToSubagentEvent`; `askQuestion` / `promptUserDialog` stay pending on the session and mount composer chrome only when that session is focused (no parent LLM auto-Respond for either).
- **AskQuestion (root):** pending questions stay on the session (`PendingAskQuestions`). Composer `AskQuestionPopover` (`_pendingAskUi`) mounts only for `ActiveSessionId`. Unfocused `OnParentEventsChanged` is `Notify()` only; `MaybeOpenAskUiForEvent` no-ops unless the parent is focused. Rejoin (`FocusSession`) remounts from still-pending session state. No auto-focus, toast, or “needs input” badge.
- **PromptUserDialog (root):** same wait-for-rejoin contract as AskQuestion (`PendingUserDialog` / `_pendingUserDialogUi` / `PromptUserDialogModal`). Choice / Skip completes via `RespondToPromptUserDialog` (JSON `{ action, skipped }`). Mutual exclusion with AskQuestion (one pending interaction at a time).
- **New session:** `StartNewSessionAsync(agentMode, modelSlugId, workDirectoryId)` — workdir required → resolves provider kind → `OpenAiCompatibleAgentSession` or `DemoDysonAgentSession`
- **Switch agent mode (submit):** `PromptAsync(prompt, agentMode)` applies mode when the picker differs from `session.Mode` (via `ApplyAgentModeCoreAsync`) before the turn — rebuilds system prompt + available-models suffix, bumps `SystemPromptGeneration` (OpenAI `prompt_cache_key`), persists `AgentMode` + `SystemPromptSnapshot`; on a real change appends a completed **`ModeSwitch`** turn (`Instruction` = `From→To`, UI banner “Switched to {to}”) **before** the Normal user turn; busy-gated; resume / focus syncs the composer picker from `session.Mode`; leaving Plan drains any buffered completion auto-turns. Empty-session CTAs also call `SetSessionAgentModeAsync` immediately (Plan / Ask) without waiting for Send (same apply path → ModeSwitch, then optional DisplayInfo).

- **ModeSwitch (mode boundary):** `session.AppendModeSwitchTurn(from, to)` from host `ApplyAgentModeCoreAsync` — completed immediately, no inference; included in Completions/Responses as a short harness user message (UI banner is not an assistant message)
- **Switch model:** `SetSessionModelSlugAsync(modelSlugId)` — same provider kind only; rejects switching **to** a disabled slug; swaps live `session.Provider`, resets composer effort to the slug’s `DefaultReasoningEffort` (pending kept in sync for New Session), and persists `ModelSlugId` + `ReasoningEffort`; **does not change agent mode** (`session.Mode` stays put; Home `OnHostChanged` only remounts the composer picker when `session.Mode` actually changes, so a pending picker selection survives model/effort/token Notify); cross-kind (demo ↔ OpenAI) rejected (`LastError`: start a new session); while busy, validates then stashes the slug and applies it after the turn finishes (before draining the prompt queue) so the current turn stays on the old provider; with no session, updates pending effort for the next New session
- **Session effort:** `SetSessionReasoningEffortAsync(effort)` — overrides session `ReasoningEffort` / live provider only (not the slug default); empty omits the request field; persists when a session is focused; blocked while busy; New Session seeds from the current composer effort (live session when focused, else pending)
